# 账号采样持久历史验收

2026-10-29，开发更新已部署，未发布 GitHub 版本。

## 行为

- 只记录原有官方额度 HTTP 请求的成功结果。缓存重放不追加，刷新间隔、可见性、限流和服务端冷却不变；没有新增轮询或历史网络接口。
- 使用实际请求账号的稳定 SHA-256 摘要作为本机目录标识；浏览器不接收该标识。当前账号查询仍受原来的 scope／generation 门控制，旧回包不能覆盖新账号。
- 成功采样追加在安装目录的 `native-patch/account-usage-history/<URL安全账号摘要>/UTC日期.jsonl`。记录字段只有 `at`、`used`、`reset`、随机 `segment`；没有原始账号 ID、令牌、凭证或会话正文，不上传。
- 不再自动裁剪四小时，也不随 Helper 退出清空。重启后读取同一账号的已保存历史，切换账号各自保留；按区间读取相关日期及最早／最晚边界日期，不把全历史加载进内存。
- 升级和卸载保留历史目录。数据独立于安装包，已加入忽略规则；未来发布包继续使用已有文件白名单，不收集本机历史。

## 覆盖与错误

查询只使用所选 `[start,end]` 内的真实成功样本。少于两点保持未知，端点不完整时标记部分覆盖；Helper 重启、换号或请求失败后采样段变化显示“采样存在间断”。同一周额度周期内可以显示带间断标记的已知端点差值，跨重置或计数回落始终不拼接、不补算。

写入采用追加并落盘，不重写旧记录。断裂末行保留原字节，补换行后继续追加；所选文件损坏／不可读时不生成消费值。首次读取文件尾失败时不缓存未知末值，释放锁后重读再追加，避免错误恢复时乱序。写入错误只影响历史状态，不把正常官方额度返回改为失败。

页面明确区分“历史保存失败”“历史暂不可读”“历史记录损坏”。历史区间和采样区间包含年份；原位切页、可打断动画、请求与区间关联保持不变。

旧版只存在进程内存中的记录没有可靠导出接口，无法在进程升级后补回。本次持久历史从启用后的真实成功采样开始；开始采集前和从未采集的区间仍是未知。

## 实机

初次部署 Helper 后保存了一条正常启动请求的成功记录；随后只重启 Helper，旧记录字节前缀完整保留，新成功记录追加到同一账号文件，采样段不同。原 Codex 会话未重启。

最终 Helper 216932 单实例无窗口，Doctor 为 `Active`。统计页读回了重启前的原始采样，返回 `partial + hasGaps` 且没有历史错误，界面显示采样间断。无水平溢出、仅一个 popover，切页后无动画或临时图层残留；验证期间官方请求标识未变。验证没有额外调用官方 HTTP，两个 Helper 启动都沿用原有正常启动请求。

私有文件副本、重启检查、界面元数据、截图和回滚备份只保存在忽略目录 `.runtime-test/account-history-20261029/`，不附到公开方案。测试记录中一次本机验证脚本读取 WinPS 5.1 UTF-16 报告失败，改为 UTF-8 后验证通过；生产历史文件始终使用 UTF-8，不受影响。

未进行长期连续运行或实际周重置验收；相关跨日／跨重置、损坏和恢复路径使用合成数据验证。

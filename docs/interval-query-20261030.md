# 区间查询页改进 · 2026-10-30

用户确认问题同时涉及时间难选、结果难读、查询慢或反馈不清。本轮修订操作流程，保留侧栏内原位展开与现有用量算法。

- 开始／结束分别成组，日期和时间独立编辑。日历按钮复用日统计已有的自绘日历，选择日期保留时分秒；仍可手动输入任意有效日期时间。
- 两个端点各有独立的原生滑轨和命中区域，避免默认一小时在同一轨道上压成两个重叠手柄。键盘保持秒级调整，滑轨仍在输入日期范围内微调。
- 滑轨下方新增 `5min / 10min / 30min / 1h` 四段快捷切换，独占一行，下一行保留当前时长与右对齐的“查询”。快捷项填写截至点击时刻的最近时段，精确到秒并支持跨午夜；不自动查询。手动滑动或输入其他时长会取消选中，任意区间仍可使用。选择标记以 200ms 平移衔接，可随时反向；减少动态效果和后台时立即完成，保留键盘与高对比度模式。
- 日期、时间、拖动、键盘调整都只修改草稿，统一点击“查询”。替代早期松手／键盘结束就提交的行为，减少不必要扫描。同一区间的重复在途点击被抑制，新的有效区间仍可重新查询。
- 发布复核补充修复：已提交区间独立保存，返回日统计切换日期、修改参考套餐或重试时只复用上次提交值，不能夹带未查询的快捷项或无效草稿。
- 读取时查询按钮原位显示“读取中…”，不新增状态行，不清空旧结果。旧结果仍显示它实际对应的区间；旧请求或不同区间的回包不能覆盖新请求。
- 结果继续比较本机估算与账号实测。部分采样的实际覆盖时间放到下方全宽行，保留采样不足、间断、跨重置和存储异常提示。

## 性能范围

改动前单次实机暖查询往返约 256ms，改动后一次约 250.8ms；这只是两次观测，不能视为加速对比或首次读取承诺。主要改善是减少隐式查询、阻止重复在途提交并提供即时反馈。

后端已有文件增量读取和缓存，但每次查询仍会枚举现存日志并重建去重／继承索引。没有证据证明本轮慢感来自该路径，因此未新增缓存、取消队列或轮询，也未改扫描和计算逻辑。冷启动及大日志规模的长期耗时尚未量测。

# ModelDial 参考额度同步修复

2026-11-03 实施记录，整合入 [v2.6.3](releases/v2.6.3.md)。这里同步的是第三方参考周总量，独立于官方账号额度请求。

## 确认的原因

本机缓存最后成功为 2026-10-30；此后尝试均保留 `REFERENCE_CHECK_FAILED`。使用同一 Helper 匿名网络栈读取当前页面成功，不能把此次失败归因于网络不通。

当前 [ModelDial 页面](https://modeldial.com/subscriptions?period=week&view=insights)有以下变化：

- “Token 单位：亿”改为“Token：亿”，Pro $100 ID 从 pro-5x 迁为 pro-100；旧解析器因此拒绝整页。
- 订阅模块依赖表目前有六个同站资源，数据模块增至 770,050 字符，超过旧 512KiB 上限。
- 数据模块明确将 openai-pro-20x 映射至 openai-pro-200，套餐名从 Pro 20x 迁为 Pro 200；同一 canonical 数据在模块中重复出现两次。旧 literal ID 查找无法找到它。
- 原流程先解析当前套餐，失败后根本没有检查旧档，却一起标为失败，造成两条参考链路耦合。

## 修复与策略

继续严格校验亿 Token、周周期、提供商、USD 和套餐，不把月值当周值。兼容两种单位文案和 Pro 100 标识；HTML 最多读取 524,288 字符、静态脚本最多 1,048,576 字符，缓存文件仍限 512KiB，同站白名单最多八个候选，不执行脚本。

旧档迁移要求来源明确的 ID 映射及同模型 previous_record_id、倍率和前后周字段的一致性，不能直接把任意当前 Pro 200 行当旧 20x。只读取来源的 weekly_tokens／weekly_api_equivalent_usd，不自行乘二填值。相同 canonical literal 允许去重；冲突数据仍失败并保留旧基准。

只含套餐 ID 的元数据模块不作为额度数据：候选还须包含明确周字段。验证按真实顺序重放 49,074 字符元数据模块，再读取 770,050 字符数据模块；真正数据模块若校验失败则保留旧数据，不吞错继续猜测。JSON／.NET／页面浮点往返允许机器精度误差，校验容差不用于改变来源值或估算公式。

当前套餐与旧档分别尝试、分别记录真实成功时间。完整成功后 24 小时再查，失败按 1／3／6 小时退避并封顶，尝试时间和失败计数在 HTTP 前写入；重启不提前，不删除缓存或伪造当前时间。失败仍保留已确认值，尚无成功缓存时明确显示快照。

ModelDial 来源链接失败时直接显示“更新失败”，悬停可查上次成功、最近尝试与下次检查时间；恢复成功后显示实际核对日期。沿用现有状态位置，不新增状态行。

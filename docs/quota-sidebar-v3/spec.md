**实装视觉修订（2026-09-27，方案讨论后）**：按 `../codex-bar-ui-proposal-20260926.html` 的参数在当前组件中实现，示意文件保持不变。以下修订优先于下文历史原型参数：

- 设置继续使用带 `role="switch"` 的原生 checkbox；用 `:checked` 驱动自绘 28×16px、99px 圆角 track 和 12px thumb。off `#CFC9BA`、on `--cq-fill`、thumb `#FDFCF8`；键盘焦点 2px outline，强制颜色模式使用系统色。保存、通知权限、跨窗口同步沿用原实现。
- 弹层方案 A：宿主 surface 90% 不透明、`blur(8px)`、无边框，阴影不变。不支持模糊和高对比度环境使用方案 B：不透明 + 0.8px 边框；实机性能或可读性不足时亦回退 B。
- 真实 Pro 单 Weekly：`本周 + 42px 细条 + 已用百分比 + 10px 时间环 + 上箭头`；真实 Plus 双窗口：`5h 已用百分比 · 本周 + 24px 细条 + 已用百分比 + 环 + 上箭头`。只有 Weekly 绘条；完整“已用”语义保留在入口无障碍名称和提示、弹层行及进度条标签中。哪个窗口低于剩余阈值，哪个数字变 warning；细条仅在 Weekly 越限时变色。
- 图形入口 32px；API、未知窗口组合、无数据及实际宽度放不下图形时使用 30px 文字入口。高度改变后重新读取头像与列表列矩形，按同一公式推导 footer 底距。`2+32=10+24=34` 仅是宿主的一种实测情况，不能把 2 或 34 写成接口常量。
- 低额度“剩余可用”与数字合为同一行，保留明确数值并 warning 化；极窄列可自然换行。设置分组用 1px divider，诊断入口 11px muted。
- 默认收起、唯一入口、实测弹层边界、时间戳推导及请求/账户隔离保持不变。最小填充按后续 L2 修订为 3px。实装和人工验收证据见 `implementation.md`。

**L2 低值态修订（2026-09-27，用户确认按推荐实施）**：依据用户提供的 `codex-bar-proposal-20260926.html` 的 L 节，浅色填充改为暖赭 `#8E4617`、轨道 `#E2D8C4`，横线高度仍为 2px、填充最小宽由 2px 改为 3px；额度数字字重 600、字距 -0.01em，“已用”保留 11px 常规字重。圆环改为 10px、描边 2.75，数值仍只由重置时间推导。深色填充混合宿主前景 65% 与暖赭基色 35%，继续使用宿主表面和现有深色轨道；强制颜色模式继续系统色回退。本次授权替换旧轨道色、最小填充和圆环尺寸约束；原型中的底部更新时间不恢复，状态沿用标题栏方案。

**X-A 展开态修订（2026-09-27，更新方案）**：真实 Pro 单本周和 Plus 双窗口采用数字—细条—时间环/日期/“重置”的焦点合并行。本周居首，数字 20px/600/−.02em，百分号 11px；保留可见“本周 · 已用”以明确窗口及数值语义。Plus 的 5h 副行使用 13px 数字、1.5px 轨道、9px 时间环（描边 2.75）；最小填充仍为 3px。低额度“剩余可用”在对应行内提示，窄宽可换行。头部为 26px，按后续反馈提供刷新、设置和“收起额度”按钮。列表列中的入口在展开后被覆盖，关闭可点击收起按钮、按 Escape 或点击外部；折叠导航栏中的图标仍可再次点击关闭。无常驻时间/状态行，API 与未知窗口组合保持既有数据布局。按内容容器实际宽度让日期换行，不设置固定弹层尺寸。重排与按分钟/恢复可见的时间更新共用窗口顺序，防止 Weekly 与 5h 的环/日期串行。

## 0. v0.3 变更摘要（改动原因优先）

Codex 改版后账号控件从列表列底部移到最左侧导航栏，旧稿假设的落点已不存在。对 2026-09-26 实机截图（1716×870，DPR 1.25）采样后，旧稿的每一项共享几何都与真机不符：

| 项目 | 旧稿 | 实机实测 | 影响 |
| --- | --- | --- | --- |
| 导航栏宽 | 62px | **51px** | 入口左边缘、收起态堆叠位置全部偏移 |
| 列表列宽 | 298px | **238px** | 弹层 272px 溢出量算错 |
| 头像直径 | 32px | **24px** | 见下方对齐公式，旧稿对齐是碰巧成立 |
| 头像距底 | 16px | **14px** | 整个底部堆叠下移 2px |
| 导航按钮 | 42px | **36px** | 图标节奏与间距不对 |
| 导航行高 | 38px | **30px** | 列表密度偏松，行距实测 31px |
| 入口高度 | 32px | **30px** | 与头像上沿对齐的前提 |

**最关键的一条**：旧稿把额度入口和头像都写成 32px 高、同底距，所以"上沿对齐"是两者高度相等导致的巧合。实机头像只有 24px，入口若维持 32px **且不重新推导底距**，上沿会差 8px。高度本身不是约束，对齐公式才是；当前图形入口 32px 会同步重新测量底距。

v0.3 把对齐改为**推导关系**而非两个独立常量：

```
footer-bottom + trigger-height = avatar-bottom + avatar-size
       8      +       30       =      14       +      24      = 38
```

改任一项都必须重算另一项。`?check=1` 已内置断言，回退会立即报 FAIL。

## 1. 已确认的方向

- 主入口放在项目列表侧栏底部，固定留位，与列表滚动区域分开。
- **收起额度条的可见上沿与最左侧头像圆形可见上沿对齐**。展开后卡片向上增高，保持该额度条的真实底边，不再要求展开卡上沿与头像对齐。
- 常驻入口为一行；点击后向上展开紧凑额度卡。
- 视觉依据是用户提供的 Codex 原生三点菜单截图。额度卡借鉴该菜单的底色、边框、阴影、字体和图标语言；圆角按后续要求与收起条一致。
- 本轮交付 HTML 示意、规格、交接说明和原图。**不实现、注入、构建、部署真实额度控件。**

## 3. 布局与精确对齐

### 常驻入口

| 项目 | 原型值 / 约束 |
| --- | --- |
| 头像直径 | **24px**（实机实测 30 物理 px ÷ 1.25） |
| 额度按钮可见高度 | 文字 **30px**；图形 **32px**，同步按实测重算底距 |
| 头像距内容区域底部 | **14px** |
| 入口 / 头像上沿误差 | `abs(trigger.top - avatar.top) ≤ 1 CSS px` |
| 入口左右留白 | 侧栏内各 8px；按钮内部各 8px |
| 入口外观 | 实装：宿主表面色的 82% 半透明底、18px 背景模糊、1px 浅边框；圆角跟随宿主 `--radius-sm`。悬停及打开时加深底色；高对比度时使用不透明底色 |
| 套餐徽章（P1） | 收起额度条最左侧显示真实 Pro / Plus；与弹层标题共用同一徽章样式和更新函数。16px 高、9.5px/600、字距 .02em、内边距 3px 7px、圆角 99px，无描边、渐变或阴影。Pro 使用额度填充色与 10% 柔底（浅色 #8E4617），Plus 使用宿主前景 72% 文字、7% 柔底。强制颜色模式使用系统色；入口无已知官方套餐时不显示 |
| 列表关系 | 列表独立 `overflow:auto`，footer 为正常布局留位；不盖住最后一项 |
| 收起态堆叠 | 入口 / 帮助 / 头像竖排，间距 14px，底部留白 14px |

对齐由共同公式保证（见第 0 节），不是两个碰巧相等的常量。实测帮助图标底到头像顶约 24.8 CSS px，按 36px 按钮居中反推为 14px 间距，误差 1.3px，视觉上不可辨。
原型用共同的底部留白实现对齐，没有用固定屏幕坐标修补。辅助线开关可直接检查两者的可见上沿。
未来接入真实 Codex 时，应读取当前宿主头像 / 侧栏的真实几何关系，不能把原型头像或 footer 坐标当作宿主接口。

2026-09-27 更新方案 P1：套餐徽章随入口信息共同淡出/恢复，展开卡采用同一徽章。侧栏折叠为导航图标时隐藏入口徽章；宽度不足时沿用文字摘要回退并保留套餐名，不缩短 Pro 42px / Plus 24px 本周细条。刷新失败保留上次成功套餐，账户切换立即清除，按钮无障碍名称包含套餐。API 已有套餐名称在弹层中使用中性徽章，不因服务商套餐恰好名为 Pro 就使用官方 Pro 强调色；无套餐名时不编造。API 入口继续保持余额摘要。

导航栏实测：宽 51px、按钮 36px、图标约 20px、首图标距顶约 8px、按钮间距约 7px。列表列实测：宽 238px、导航行 212×30px、行距 31px、左内边距 8.8px，右侧多出的约 10px 是滚动条槽位。

### 弹层

- 宽度取原生菜单 **272px** 与「所在列表列实测宽 − 左右各 8px」的较小值，**保证不越出列表列**。新版列表列为 238px，因此实际渲染宽度为 **222px**。用户明确要求不溢出，优先于沿用截图宽度。
- 宽度与位置在打开时按 `document.querySelector('.sidebar')` 的**实测矩形**计算，不使用 `--sidebar-width` 常量——该常量是原型标称值，媒体查询下会与真实列宽脱节。收起侧栏后列表列不存在，此时不受该约束，只保证不越出视口。
- 默认双窗口高度约 **180px**；单窗口随内容自然缩短。设置替换内容，不在卡片下方继续堆叠。
- **2026-09-27 用户纠正**：列表列内在原位置向上展开，展开卡与收起额度条共用实测底边和左边缘；取消两者之间的 8px 间隔及下方空条。收起入口只保留布局测量用的占位，展开时其背景、边框、阴影、模糊和全部内容透明，退出 Tab 顺序。X-A 后续实机反馈补回头部“收起额度”按钮，同时保留 Escape / 外部点击关闭。
- 不拉伸为整条侧栏，不添加背景遮罩，不改变正文或列表的布局。
- 窗口空间不足时优先保证卡片完整可见。列表列内顶部保留 12px，底边沿用原入口真实位置；左右仍按实测列边界限制。导航栏图标旁的弹层保留原有视口 12px 安全区。矮窗口限制卡片高度并允许内部滚动。
- 收起侧栏时，将同一个入口节点移入导航栏底部堆叠（帮助按钮上方），使用 36×36px 仪表图标按钮；展开向右，避免按钮或卡片离屏。
- 侧栏展开时只显示列表底部文字入口，收起时只显示导航栏图标，不同时常驻两份。

## 5. 信息与语义

### 常驻条

- 双窗口：`已用  5h 28%  |  本周 63%`。
- 单窗口：`已用  本周 63%`，不补造 5h 窗口。
- API：`API 剩余  $24.80`，不映射成官方账户窗口。
- 无数据：`额度  暂不可用`，不用 0% 代替未知。
- 低额度：保留数值，增加微小状态点；详情明确显示剩余额度，避免只靠颜色表达。
- 更新失败：保留上次成功数值，详情写明更新失败；真实实现还需展示上次成功时间。

### 展开卡

1. 一行轻量标题：额度、套餐短标签、刷新、设置。
2. 每个实际窗口一组短行：窗口名与已用比例；2px 细线与"时间圆环 + 绝对重置时刻"。
3. **2026-09-27 实装修订**：底部不再增加状态或更新时间行。原标题位置在“额度 / 刷新中… / 更新失败 / 暂不可用”之间切换，刷新按钮复用旋转、完成、警告图标。成功反馈在按钮处短暂显示约 2 秒；失败原因、上次成功时间和限流重试时间通过悬停或键盘聚焦刷新按钮查看。详细状态继续由不占布局空间的 live region 向读屏播报；刷新或失败不改变卡片高度。

官方横线表示**已用**，API 横线表示**剩余**，标签必须随语义出现，不反转现有数据含义。
时间圆环表示**窗口已流逝时间比例**（v0.2）：横条答"用了多少"，圆环答"过了多久"，并排构成"时间 vs 用量"对照——环快条慢即省着用，条快环慢即该悠着点。圆环与倒计时文字同源（elapsed = 1 − 剩余 / 窗口时长），两者不得出现不一致。
API 余额行**不加**圆环：金额无时间窗口语义，不虚构进度。
无真实总额的 API 数据只显示金额，未来实现不得推算百分比。
额度窗口互相独立，不能把两个百分比平均成一个“总体额度”。

原型场景覆盖双窗口、单窗口、API 余额、低额度、已有数据更新失败、首屏暂无数据。
更多未知窗口仍应逐条呈现真实数据；这不是当前静态样本已覆盖的生产行为。

## 6. 交互

- 单击入口打开；列表列中展开卡覆盖原入口，可点击右上“收起额度”、按 Escape 或点击外部关闭。折叠导航栏模式的图标可再次单击关闭。
- 点击外部、按 Escape 关闭，不使用模态遮罩。
- 使用原生 `popover="auto"` 管理顶层和轻量关闭；额度卡和三点菜单互斥。
- 按键盘 Enter / Space 可以触发入口；Tab 可进入刷新、设置等操作。
- Escape 关闭后焦点返回额度入口；点击外部时保留用户新点击的焦点，不强行夺回。
- 设置在同一弹层中替换内容，返回按钮回到额度；不生成第二张悬浮卡。
- 刷新只模拟约 650ms 等待；不改变示例额度，不请求服务，不承诺实时结果。
- 改场景会重绘示例并展开卡片；主题、辅助线、场景切换均属于原型评审工具。
- 设置复选框仅在本页面内生效，不写 localStorage、不发通知。12 小时制会改变 5h 示例时刻。

## 7. 动效

所有值为本轮建议，**不是从静态截图提取到的原生动画**。

| 动作 | 参数 |
| --- | --- |
| 打开 | M 方案：240ms，`cubic-bezier(.2,.8,.2,1)` |
| 关闭 | 180ms，沿实测入口方向收回 |
| 形变 | `clip-path:inset(... round ...)` + translate；从真实入口矩形的裁切片段展开，半径取宿主实际值 |
| 内容 | 不缩放文字；入口信息 100ms 淡出，弹层内容延迟 80ms 后用 160ms 淡入 |
| 设置页切换 | 160ms；一次性预留两端最大高度，用裁切和平移过渡，结束清理临时样式，不逐帧改变 height/top |
| hover | 背景 110ms 过渡，无弹跳 |
| 减少动态效果 | 取消位移、缩放、旋转及过渡，即时切换状态 |

复用现有 Motion mini / WAAPI 与原生 popover 的离散 display / overlay 过渡，不维护动画队列。列表列内展开卡覆盖原入口位置，不再留下另一条边框或箭头；通过“收起额度”按钮、Escape 或外部点击收回。键鼠打开后焦点进入卡片，按钮收起及 Escape 后回到恢复可见的额度条，外部点击保留新焦点。收起侧栏时仍从真实图标矩形左中向右展开。
连续开关不锁定输入；终止上一段并清理其样式后转向目标端点，不能累积弹跳、残影或多个弹层。减少动态效果及隐藏页面直接切换。
不在日常开关中移动整个侧栏，不用模糊掩盖布局跳动。

## 8. 修改入口

`index.html` 顶部 `:root` 是共同 token 区域：

- `--trigger-height`、`--footer-bottom`、`--avatar-size`、`--avatar-bottom`、`--rail-gap`：入口与头像对齐与导航栏底部堆叠；调整其中任何一个都必须按第 0 节公式重算并重新验收上沿。
- `--menu-width`、`--menu-radius`、`--menu-padding`、`--menu-shadow`：弹层密度与原生外观。
- `--popup-gap`：入口与弹层间距。
- `--motion-in`、`--motion-out`、`--motion-ease`：开关手感。
- `render()`：合成样本与文案，不是生产数据适配器。
- `positionPopover()`：离线页面的锚点定位，不是未来 Codex 的 DOM 发现逻辑。

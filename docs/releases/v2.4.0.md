# v2.4.0 发布验证

2026-10-21。安装器为当前用户已有的 Codex 官方包快捷方式补齐调试参数，使这些入口首次启动即可供额度卡服务连接；保留原包目标，没有新增启动脚本。

## 安装行为

- 只检查当前用户桌面、开始菜单 Programs 和任务栏固定目录的既有 `.lnk`，按当前注册的 Codex 包应用 AUMID 与原生 PIDL 识别，不按文件名匹配。
- 使用原生 `IShellLinkW.SetArguments` 在备份副本中准备参数，验证 PIDL、目标、图标、描述、工作目录等未变后，以独占文件句柄核对原字节哈希并写回。只补齐 `--remote-debugging-address=127.0.0.1 --remote-debugging-port=0`，保留其他参数和引号。
- 正确参数不重复追加，也不改文件时间或取得卸载恢复所有权。不同调试端口/地址、未闭合引号等冲突明确失败，避免依赖重复开关顺序。
- 首次原件与恢复记录保存在运行目录 `official-shortcuts`。升级保留首次原件；安装失败回滚本次修改，快捷方式回滚失败也不阻断原文件/任务的恢复。
- 卸载只还原目标和哈希仍匹配安装器写入版本的官方链接，不删除它们。用户后续改动、替换目标或损坏原件时保留当前链接及备份，明确报告未恢复项。
- 无包或无匹配链接分别报告 `PackageNotFound` / `NotFound`，不虚报配置成功。虚拟开始菜单应用入口不是可写 `.lnk`；未配置入口继续沿用既有启动逻辑。`-SkipTaskRegistration` 不加载模块或操作快捷方式。

`official_shortcuts.ps1` 只在安装与卸载阶段运行，不是启动包装脚本，不加入计划任务。Helper、界面、请求限流和账户隔离链与 v2.3.1 相同。

快捷方式回归覆盖参数引号、错误包/EXE、幂等升级、升级发现新链接、外层失败回滚、状态文件首次与既有写入失败、卸载恢复首次原件、用户改动/换目标/原件损坏保护。辅助模块加载本身无副作用。

底层两参数透传已在此前本机原官方快捷方式的单次手动冷启动中验证，获得动态 loopback 端口且未发生 Helper 二次重启。本轮不退出用户会话；安装器配置成功与实际入口可见性分别报告，不能将其外推为所有未来宿主版本都兼容。

UI 与 Helper 内容哈希均与 v2.3.1 相同，本轮未重跑无改动的浏览器动效或原生启动器测试；这些基线见 [v2.3.1 验证](v2.3.1.md)。Helper 仍未代码签名。
